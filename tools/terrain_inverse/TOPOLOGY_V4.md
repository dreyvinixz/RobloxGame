# V4 — Source-pixel 2D topology audit

**Purpose:** Extend V3 line/face detection into an explicit candidate graph with shared vertices, edges, incident faces, reproducible image-space error diagnostics and optional planar registration. **This is NOT yet a terrain heightmap or 3D mesh recovery.**

## Input, scientific traceability

Original user-supplied screenshot: 1619 × 971 pixels; SHA-256:

`c166e9d711cb70b09feeee5652f2db82a587675ae0124c762532f54846b5d575`

The source image itself **has not been committed** to this repository. The GitHub Actions workflow therefore processes a clearly labeled **synthetic test fixture**, not the original terrain. Local first-pass measurements (below) were generated from the original screenshot plus V3 observations whose SHA was verified against the original bytes. There is **no automatic substitution by a procedural map** in V4.

To run over the original screenshot (Python 3.11+):

```bash
python -m pip install -r tools/terrain_inverse/requirements.txt
python -m tools.terrain_inverse.topology_v4 \
  --image '/path/to/image(20261016-021821).png' \
  --output topology-v4-original
```

For rapid reproducible reconstruction using a cached V3 result (will fail if the SHA or ROI differs):

```bash
python -m tools.terrain_inverse.topology_v4 \
  --image '/path/to/image(20261016-021821).png' \
  --v3-report /path/to/v3/wireframe_report.json \
  --output topology-v4-original
```

## Algorithm

1. Read mandatory raw image, hash its exact bytes, recompute dark-stroke evidence directly from pixel intensities.
2. Import V3 closed-cell candidates; reject degenerate, collapsed, duplicate, nonconvex or unsupported polygons.
3. Match candidate corners using KDTree radius 3px and disjoint-set union (tracked uncertainty; not perfect grid reconstruction).
4. Register unique edges, incident faces, component count, Euler characteristic and boundary/nonmanifold edges. Faces have 3–6 sides; **only 3 and 4 are counted as triangles and quads**.
5. Build a second, independent graph of observed Hough line segments snapped to observed junctions, without inventing faces or diagonals.
6. Draw source-original-vs-topology overlays and score candidate edge support and observed-pixel coverage. Both metrics are *2D in-sample descriptive statistics*, not independent validation or 3D reprojection.
7. Optional planar homography from 4+ **independently verified coplanar** control points, with RANSAC reprojection error. No automatic camera calibration is claimed when anchors are absent.
8. Export pixel-graph JSON and an **image-plane OBJ** (all heights zero). OBJ exists only to visualize accepted face topology in a 3D viewer; it is **not** `terrain_initial.obj` and is not a playable Roblox island.

| Matched line graph edges | 1078 |
| Line graph vertices | 1689 |
| Connected line components | 618 |
| Pixel support within 3px of accepted 2D candidate edges | ~95.6% |
| Coverage of all observed strokes by face edges (2px tolerance) | ~6.3% |

The high edge-support percentage is **selection-biased** because the algorithm explicitly chooses faces whose edges coincide with image strokes. The ~6.3% coverage and 139 disconnected components expose a far bigger remaining problem: V3 currently misses much of the coherent drawn wireframe. These figures should **not** be represented as reconstruction accuracy.

Most critical geometry limitations:
- Source image was generated by AI and need not describe a consistently connected geometric mesh.
- Mountain sections are dark and textured, causing systematic under-detection by the median-background contrast threshold.
- Trees, road markings, coastal details and harbor structures create false junctions and polygons.
- The water-plane grid provides insufficient unambiguous metric control points for automatic camera calibration in this stage.
- From one image alone, the 3D altitude of all mesh vertices is mathematically underdetermined.
- A 2D segment snapped to two junctions may still be a false-positive edge.

## Files

- `vertices.json`, `edges.json`, `faces.json`: unverified image-pixel topology candidates.
- `segment_graph.json`: independently snapped line/junction graph, not inferred faces.
- `camera.json`: normally `status=not_estimated`; with verified controls, contains **planar homography only**.
- `topology_overlay.png`, `observed_segment_graph_overlay.png`: 2D overlays.
- `image_vs_topology_comparison.png`: original / observed candidate topology / stroke comparison side by side.
- `screen_space_face_candidates.obj`: deliberately flat pixel-space face preview, **not elevation**.
- `topology_report.json`: hash, parameterized metric diagnostics and limitations.

## Optional planar control input

Example `controls.json` format, with four independent correspondences from a **single genuinely planar region** (these are dummy examples, not actual map measurements):

```json
{
  "points": [
    {"world_xy":[0,0],"image_xy_px":[30,40],"on_same_plane":true},
    {"world_xy":[1,0],"image_xy_px":[110,44],"on_same_plane":true},
    {"world_xy":[1,1],"image_xy_px":[125,120],"on_same_plane":true},
    {"world_xy":[0,1],"image_xy_px":[20,115],"on_same_plane":true}
  ]
}
```

Use `--plane-anchors controls.json`. An estimated plane homography is **not** a full intrinsic/extrinsic 3D camera, depth map or terrain model.

## Next gate: evidence is not enough for 3D conversion

V4 cannot pass a connected original-mesh fidelity gate (139 islands). Next work should segment foreground objects and illumination separately, identify grid-line families robustly in bright and dark rock regions, solicit verification of planar anchor correspondences, and retest graph connectivity on manually labeled patches **before** any 3D heightfield export or Roblox integration.
