# FL-018 — Studio multiplayer acceptance

**Date:** 2026-10-15  
**Environment:** Roblox Studio Place1, Rojo-synced FL-018 source, `StudioTestService.ExecuteMultiplayerTestAsync(2, "FL018_Acceptance")`.

## Result

**PASS** — one simulated server and two simulated clients completed the acceptance harness.

```text
PASS | FireWeapon server-validated | Azul vs Laranja | scores Azul=1 Laranja=0 | spawn e escudo validados
```

The harness placed the clients on opposing teams and checked that the initial spawn ForceField blocked damage and expired. It then sent a valid `FireWeapon` RemoteEvent payload from one client using the center-camera ray, allowing the normal server validation and `DamageService` path to process the elimination. The opposing team's score and the attacker's `KOs` / target's `Deaths` incremented. The target respawned at its team's spawn with protection reapplied.

The shot was submitted by the client-side test harness through the same remote; this was not a physical mouse click. The test did not advance the round clock to observe timeout, intermission, or score-to-win transitions. Those conditions were checked in the server implementation but remain without runtime transition evidence.

## Coverage

- Two teams created and both test players assigned to opposing teams.
- Initial spawn protection blocks damage and expires.
- Server-validated `FireWeapon` request reaches damage processing.
- Friendly-fire and inactive-round checks are in the server damage path.
- Elimination updates team score and leaderstats.
- Respawn uses the correct team spawn and restores protection.
