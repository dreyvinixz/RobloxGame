# FL-026 — Performance stabilization (partial)

**Date:** 2026-10-15  
**Branch:** `feat/FL-026-performance-stabilization`, based on FL-025/PR #57  
**Studio/Rojo:** S2 report uses Roblox Studio 0.743.0.7431133. A limited S4 Place1 idle capture was made with the FL-025 vehicle implementation present; its spawn pivot was temporarily set to the committed Y=3.15 value and restored after Play. This is not a synchronized, equivalent S2/S4 comparison.

## Evidence
- The only numeric baseline is the documented S2 idle local Studio sample: 30.008 seconds, 120.03 average FPS / 100.94 p1, RenderCPU 7.17 ms, RenderGPU 2.49 ms, 29 draw calls, 46,779 triangles, and total process memory average 2,104.39 MB.
- Preliminary S4 idle sample: 30.022 seconds, 1,348 RenderStepped frames, 56.21 mean / 58.06 median / 8.91 p1 FPS. The LibMP snapshot contained 62 CPU frames with 15.71 ms mean, 14.94 ms median, and 23.04 ms maximum frame time. `Stats:GetTotalMemoryUsageMb()` averaged 1,544.68 MB (1,531.89–1,550.27), using the same Stats API as S2. Draw calls, triangles, and RenderCPU/GPU frame times were not obtained in this run.
- The S4 sample is not comparable: nine other Studio instances were in Play both before and after capture; the loaded Place1 scene also contained FL-013 content and the FL-024/025 vehicle, unlike the S2 FL-016 arena plus three props. Viewport and quality settings were not matched. Do not attribute the lower FPS or the 62-frame LibMP window to the game branch.
- Source review found a single idempotent Heartbeat connection and per-player event tables cleared on PlayerRemoving. This cannot prove runtime leak absence. No warning count was collected for the S4 source.
- The three obstacle raycasts run only while a driver is active; without profiler attribution, no code optimization was justified.
